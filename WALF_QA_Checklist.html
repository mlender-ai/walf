실사용 QA 체크리스트첫 테스트 상품 — BADBLOOD Mystic Nylon Track Jacket Navy / M

등록 → 운영자 검수 → 추적 → 수배 승인 → 결과 알림 → 종료iOS 시뮬레이터 빌드 · 로컬 서버 · 2026-11-08

이 문서는 실제 기기와 실제 운영자 입력으로 한 바퀴를 돌며 확인할 항목이다. 체크 표시는 이 브라우저에만 저장된다. 판매처 탐색과 채널 게시는 자동이 아니라 운영자가 실제로 확인한 뒤 어드민에 기록하는 방식이다.

01 · SETUP · 준비

서버를 켜고,
앱을 붙인다

서버 · 어드민

cd ~/Desktop/WALF/server
npm start
# 어드민  http://localhost:4300/admin
# 비밀번호  server/.env 의 WALF_ADMIN_PASSWORD
# 운영자 이름은 로그인 때 적은 이름이 일지에 남는다

앱

# 시뮬레이터 (Xcode 필요)
cd ~/Desktop/WALF/app
npx expo run:ios
# 이미 설치된 빌드를 쓸 때
xcrun simctl install booted ~/Desktop/WALF/builds/WALF-0.1.0-sim.app (zip 압축 해제)
# 실기기(같은 Wi-Fi): MY → 서버 주소 → http://<맥 IP>:4300

첫 QA는 빈 DB(server/data/walf.db)에서 시작한다. 자동 검증에 쓴 데이터는 별도 임시 DB에서 돌고 지워졌다.

UNIT29 / 29상태 규칙 테스트 — 1인 1벌, 168시간, 하루 1회·최대 7회, 실패≠매물 없음, 수배 승인≠게시, 제보 알림, 모의 전파, 데이터 삭제
E2E17 / 17BADBLOOD 상품으로 앱 API와 어드민 폼을 실제 HTTP로 등록부터 종료까지(임시 DB, 운영자 입력은 모의)
SIMULATOR1 바퀴iPhone 17 Pro · iOS 26.5에서 앱 화면으로 등록 → 출발 모션 → 운영자 확인 → 수배 동의 → 게시 → 유력 후보 → 구매 가능 → 외부 링크 → 구매 확인
REVIEW결함 10건 수정독립 리뷰가 찾은 정책 위반·상태 불일치·권한·예외 경로를 고치고 회귀 테스트 11개 추가
  • 앱 타입 검사 — tsc 오류 0
  • Release 빌드 — 개발 서버(Metro) 없이 단독 실행 확인, 모션 줄이기 켬 → 정지 이미지 + 결과 즉시, 긴 상품명 2줄 말줄임
  • 실기기(iPhone 13 mini · iOS 27.2)에서 발견·수정 — 사진을 붙이면 맡기기가 실패(SDK 58의 expo/fetch가 예전 RN식 사진 첨부를 거부 → expo-file-system File로 교체), 실패 문구가 화면 아래에 숨어 있던 문제(버튼 위·팝업으로), 앱 안 오류를 “서버 연결 실패”로 안내하던 문제, 사진 권한 직후 선택 창이 안 뜨던 문제. 사진 1장(4MB) 의뢰 접수 확인
  • 시뮬레이터에서 고친 것 — 탭 이동 시 상태를 다시 읽지 않던 문제, 수배 동의 직후 실패 상태가 게시 준비를 가리던 우선순위, 첫 탐색 실패 안내 중복, 판매자 사진 없음 문구, 모달 상단 여백, 연결 오류 상자가 화면을 덮던 문제
  • 리뷰에서 고친 것 — 모의 탐색이 실제 알림으로 나가던 문제(이제 모의 표시 + 푸시 생략), 끝난 의뢰의 후보 수정 시 알림, 가격 미기재 후보의 오판정, 조건 변경만으로 구매 가능 승격(이제 운영자 재확인 전까지 유력 후보), 데이터 삭제 시 게시글 삭제 대기열 유실, 탐색 기록 기본값 “확인함”, CSRF 토큰·로그인 제한·쿠키 예외
  • 자동으로 확인하지 못한 것 — 실기기, Android, 원격 푸시 수신, Dynamic Type 최대·VoiceOver 낭독(체크리스트 04로 수동 확인)
