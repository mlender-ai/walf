# WALF V2.1 · Gate B 보고 — 실제 상품 큐레이션과 찾아줘 결과 화면

- 작성: 2026-11-19 · 브랜치 `feat/walf-v2.1`(Gate A 위에 이어서)
- 범위: 지시서 STEP 2(실제 상품 큐레이션 구조)와 STEP 3(찾아줘 결과 UX)
- 기존 검수 정책은 그대로예요. 판매처 후보와 대체 상품은 **운영자가 검수해 공개한 것만** 앱에 보여요.
- 실제 추천 엔진(패션 브레인)은 아직 연결 전이에요. 대체 상품은 권리가 확인된 테스트 Fixture(가상의 상품·직접 그린 그림)로만 검증했어요.

## 1. 무엇이 바뀌었나

### 찾아줘 결과 — 네 가지를 나눠 보여 줘요

| 구분 | 앱 표시 | 근거 |
|---|---|---|
| 정확한 동일 상품 | **판매처 · 같은 상품 확인**(검은 태그) | 품번이 판매 페이지에 있거나, 운영자가 직접 확인한 근거를 적었을 때만 |
| 동일 상품일 가능성 | **판매처 · 같은 상품일 수 있어요**(테두리 태그) + “확인하지 못한 점 · 참고” 상자 | 운영자가 “같은 상품일 수 있음”으로 공개 |
| 유사한 디자인의 대체 상품 | **비슷한 디자인의 옷 · 같은 상품 아님**(회색 태그) + 비슷한 점 · 다른 점 | 디자인 점수로 고르고 운영자가 공개 |
| 탐색 실패·확인 불가 | 회색 안내 상자 | 예: “확인한 판매처에서는 아직 못 찾았어요”, “왈프 팀이 판매처를 확인하고 있어요”, “이번에는 판매처를 확인하지 못했어요. 매물이 없다는 뜻은 아니에요” |

- **화면 순서:** 어떤 옷인지(식별) → 판매처 → 비슷한 디자인의 옷 → 비슷한 스타일의 브랜드(기존 DISCOVER, “브랜드 단위 추천”이라고 표시)
- **같은 옷을 못 찾았을 때:**
  - 식별은 됐지만 판매처가 없으면 “같은 옷을 파는 곳을 아직 못 찾았어요. 디자인이 비슷한 옷도 살펴볼까요?”로 대체 상품 구역이 바로 이어져요.
  - 상품을 식별하지 못했으면 제목이 “같은 옷은 아직 못 찾았어요 · 대신 비슷한 디자인의 옷을 골라 뒀어요”가 돼요. 홈 카드 버튼은 “비슷한 옷 보기”예요.
- **상품 카드:** 사진 · 브랜드 · 상품명 · 판매처 · 새 상품/중고 · 판매가(할인 전 가격은 줄 그음) · 배송비 포함 총액(모르면 “배송비 확인 필요”) · 원하는 사이즈 재고를 보여 줘요.
  - 같은 상품 카드에는 확인한 근거와 운영자 확인 메모가 붙어요.
  - 대체 상품 카드에는 비슷한 점과 다른 점이 붙어요.
- **“구매 가능”이라고 쓰지 않아요.** 카드마다 “오늘 오후 1:26 판매 페이지 기준 · 가격·재고는 바뀔 수 있어요”처럼 기준 시각을 적어요.
- 테스트 상품은 판매 페이지 주소를 앱에 주지 않고 “테스트 상품이라 판매 페이지가 없어요”로 표시해요.

### 실제 상품 큐레이션(STEP 2)

| 단계 | 내용(`server/src/curation.ts`) |
|---|---|
| 검색 | `SimilarProductProvider` 마다 후보를 받아요. 지금 쓸 수 있는 건 테스트 큐레이터(`walf-fixture-curator` / `fixture-1`, 모의 의뢰 전용)뿐이에요. 패션 브레인은 `PENDING_INTEGRATION`이에요 |
| 정리 | 모든 값이 `cleanOffer`를 거쳐요. 아래 값은 빼요 |
| 정렬 | 제품군·실루엣 3 > 디테일·소재 2 > 색·무드 1 가중치로 점수를 매겨요. **브랜드는 점수에 넣지 않아요.** 점수 0.35 미만은 빼요. 정렬 규칙 버전 `walf-design-rank-1`을 탐색 요약에 남겨요 |
| 비슷한 점·다른 점 | 종류별로 비교해 자동으로 적어요. 예: “실루엣 박시 · 디테일 지퍼 · 소재 울” / “소재가 달라요 — 코튼(찾는 옷은 울)”, “M 사이즈는 품절이에요” |
| 검수 | 운영자가 “비슷한 디자인으로 공개” 또는 “제외(사유)”를 골라요 |

정리 단계에서 빼는 값:

- 주소·추천 모델·버전이 없는 값
- 디자인 정보가 없는 상품
- 제품군이 다른 상품
- 찾는 옷과 같은 상품(같은 상품은 판매처 탐색 쪽에서 다뤄요)

**디자인 우선을 보여 주는 예:** 울 박시 집업을 찾을 때의 순서는 다음과 같아요.

1. 울 집업 블루종(0.96)
2. 코튼 캔버스 워크 자켓(0.63, 실루엣 박시)
3. 울 셔켓(0.46, 소재는 같지만 실루엣이 다름)

같은 미니멀 브랜드의 롱 트렌치 코트처럼 무드만 닮은 옷과 니트 가디건(제품군이 다름)은 고르지 않아요.

- 대체 상품도 판매처 탐색과 같은 실제 상품 후보 모양(`ProductOffer`, `relation=similar`)이에요. 상품마다 디자인 요소(`offers.style`)를 저장해요.
- 상품을 식별하지 못한 의뢰도 사진에서 읽은 디자인만으로 대체 상품을 골라요(`target_basis=style_only`).

### 운영자 검수(`server/src/offerreview.ts` · 어드민 의뢰 상세)

| 동작 | 조건 |
|---|---|
| 같은 상품 확인으로 공개 | 품번 일치 후보는 바로 공개할 수 있어요. 그 밖의 후보는 **직접 확인한 근거 10자 이상**이 있어야 해요. 자동 판정이 “다른 상품”이면 어느 쪽으로 공개하든 근거 10자 이상이 필요해요 |
| 같은 상품일 수 있음으로 공개 | 판매처 후보만 가능해요 |
| 비슷한 디자인으로 공개 | 대체 상품만 가능해요. 대체 상품을 “같은 상품”으로 공개할 수는 없어요 |
| 제외 | 사유가 필수예요(다른 상품 · 판매 종료·품절 · 디자인이 많이 다름 등) |
| 사용자 화면에서 내리기 | 공개를 거둬요 |

- 찾아줘 결과를 공개하기 전에 검수한 후보는 “공개 대기”로 두었다가, 결과를 공개할 때 함께 나가요. 알림은 한 번이에요.
- 공개한 뒤에 검수한 후보는 바로 공개돼요. 알림은 같은 날 같은 종류에 한 번만 가요.
- 같은 페이지를 다시 탐색하면 검수(공개·제외)를 새 줄이 이어받아 최신 가격으로 보이고, 같은 페이지가 두 번 보이지 않아요.
- 사용자 활동 일지에 “왈프 팀이 판매처를 확인했어요”, “비슷한 디자인의 옷을 골랐어요”가 남아요.

**V2.1 E2E에 더한 Gate B 단계**

1. 대체 상품을 디자인·실루엣 순으로 정렬해요. 브랜드는 점수에 들어가지 않고, 패션 브레인은 연결 전이며, 찾는 옷과 같은 상품은 빠져요.
2. 운영자 검수 규칙을 확인해요.
   - 품번 미확인 후보는 근거 없이 “같은 상품 확인”으로 공개할 수 없어요.
   - 제외에는 사유가 필요해요.
   - 대체 상품은 “같은 상품”으로 공개할 수 없어요.
3. 앱에서 다음을 확인해요.
   - 판매처(같은 상품 확인 2 · 같은 상품일 수 있음 1)와 비슷한 디자인 2개가 보여요.
   - 이미지가 PNG로 내려와요.
   - “구매 가능”, 제외한 후보, 테스트 주소가 앱에 가지 않아요.
   - 알림은 종류별로 한 번이에요.

**시뮬레이터에서 찾아 고친 것**

- 상품명 앞에 브랜드가 한 번 더 붙어 보이던 것
- 사이즈 재고가 근거 목록과 사이즈 줄에 두 번 나오던 것
- “상품명 핵심 단어 4/4개”처럼 내부 판정 문구가 사용자에게 보이던 것 → “상품명 일치”, “판매 페이지에 품번이 없어요”, “사진으로는 비교하지 않았어요”로 바꿈
- 비슷한 점이 네 줄로 길게 나오던 것 → 한 줄로 바꾸고, 중요도 순(실루엣 → 디테일 → 소재 → 색 → 무드)으로 정렬
- 구역 제목 아래 여백이 커서 카드와 떨어져 보이던 것
- 대체 상품만 공개한 의뢰에서 공개 시각과 “모의 데이터” 안내 띠가 빠지던 것

## 3. 제안 — 검수 전 빠른 탐색(구현하지 않음, 결정 필요)

지금은 검수 전에 “판매처를 찾고 있어요 · 왈프 팀이 확인하고 있어요” 같은 **진행 상태만** 보여 주고, 후보 내용이나 개수는 보여 주지 않아요. 더 빠르게 보여 주려면 아래 방식을 제안해요. 기존 정책(“검수 전에는 사용자에게 보이지 않음”)을 바꾸는 일이라 **사용자가 결정**해 주셔야 해요.

| 항목 | 제안 |
|---|---|
| 대상 | 품번 일치(`same_code`) + 판매 페이지를 직접 읽음 + 허용된 소스(공식몰)인 후보만. 가능성·대체 상품은 계속 검수 후 공개 |
| 표시 | 별도 구역 “자동으로 찾은 판매처 · 왈프 팀 확인 전”, 점선 태그. 가격·재고 기준 시각을 크게 적어요 |
| 알림 | 보내지 않아요(검수 후 공개 때만) |
| 철회 | 운영자가 제외하면 바로 사라져요 |
| 끄기 | 서버 설정으로 끌 수 있어야 해요(기본 꺼짐) |

## 4. 한계

1. **실제 대체 상품은 아직 없어요.** 추천 엔진이 연결되기 전이라 실제 의뢰에서는 대체 상품 구역이 나오지 않아요. 테스트 큐레이터는 모의 의뢰에만 써요.
2. **디자인 비교는 통제 어휘 태그 비교예요.** 사진의 실루엣을 직접 보지 않아요. 태그가 거칠면 점수도 거칠어요. 예: 울 집업과 나일론 코치 자켓이 “박시 실루엣”만으로 0.5점을 받아요.
3. **실제 판매처 이미지를 앱에 보여 줄 권리는 법무 확인 전이에요.** 테스트 이미지만 서버가 PNG로 바꿔 주고, 실제 판매처 이미지는 주소만 전달해요.
4. **사용자 피드백(마음에 들어요 등)과 선호(실루엣 중요 등)는 아직 없어요.** Gate D에서 만들어요. 정렬 함수는 가중치를 바꿀 수 있게 만들어 두었어요(`designMatch(want, have, weights)`).
5. **시뮬레이터는 Release 앱 복사본에 JS 번들만 넣어 확인했어요.** 네이티브 빌드나 실제 기기 확인은 하지 않았어요.

## 5. 다음 — Gate C

기다려줘의 상품 페이지 가격 감시(Price Watch)와 새 매물 탐색(Listing Discovery)을 나누고, 기다리는 동안 대체 상품을 연결해요. 판매처 탐색(`offer_searches.purpose=discovery`)과 `listings.first_seen`은 Gate A에서 이미 마련했어요.
