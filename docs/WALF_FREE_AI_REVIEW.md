## 0. 결론

1. **무료 API로 바꿔 끼워서 아낄 수 있는 비용은 거의 없다.** WALF가 돈을 쓰는 곳은 Claude 호출 두 군데뿐이다(사진 식별, 7일 수배 탐색). 둘 다 웹 검색·페이지 열람 도구가 꼭 필요하다. FreeLLMAPI와 무료 모델은 이 도구를 제대로 지원하지 않는다. 사용자 사진을 학습에 쓰는 무료 등급도 많다.
2. **실제로 비용을 줄이는 방법은 Claude를 부르는 범위를 줄이는 구조다.**
   - 제품군(카테고리)은 이미지 임베딩 MODA로 정한다. 정확도 96.3%로 로컬 VLM보다 높고, 서버 CPU에서 사진 1장에 87 ms다. 이미지 검색용으로 서버에 올리기로 한 모델(R2)이라 비용이 더 들지 않는다.
   - 브랜드·모델 식별은 무료 모델로 바꾸지 않는다. 세 로컬 모델 모두 정답 0/18이었고, 2B는 브랜드를 지어냈다. 대신 이미지 검색(MODA) + 품번 규칙 + 공식몰 검색으로 Claude가 필요한 경우만 남긴다([`WALF_COST_SCENARIOS.md`](WALF_COST_SCENARIOS.md)의 B 구조).
3. **로컬 VLM(Qwen3-VL-8B)은 카탈로그를 등록할 때 일괄 처리하는 용도로만 쓸 만하다.**
   - 소재·색 태깅, 검색 키워드, 판매 글 정리에 쓸 수 있다.
   - 조건은 세 가지다: JSON 스키마 강제, 탐욕적 생성, 사람 표본 검수.
   - 메모리 6.8 GB, 1장 약 12~14초라 4 GB 서버나 사용자가 기다리는 경로에는 올릴 수 없다. Apple Silicon 맥 같은 별도 장비에서 돌린다.
4. **추천 이유와 검색어는 지금처럼 규칙으로 둔다.** 이미 비용이 0원이고, 로컬 8B가 만든 결과와 비교해 더 나을 근거가 없다.
5. **도구는 EGM만 조건부로 시험할 가치가 있다.** Claude-Mem과 21st.dev MCP는 도입할 필요가 없다. Claude Code Setup은 새 프로젝트를 시작할 때 한 번 써 볼 정도다. FreeLLMAPI도 설치하지 않는다.
6. **가장 큰 빈칸은 유료 기준선이다.** Claude로 같은 평가셋을 돌린 적이 없다. 그래서 "무료가 품질을 유지한다"고 아직 말할 수 없다. 기준선부터 재는 것을 첫 단계로 권한다(§7).

## 3. 작업별 품질 비교와 실패 사례

### 3-1. 작업별 결과

테스트 사진은 27장이다(Met CC0 15장, ABO CC BY 4.0 12장). 유료 기준선(Claude)은 키가 없어 돌리지 않았다. 그래서 아래 비교는 무료·로컬끼리의 비교다.

| 작업 | 지금 WALF | 가장 나은 무료 후보 | 핵심 수치 | 판정 |
|---|---|---|---|---|
| 1. 카테고리 | Claude 식별에 포함 | **MODA zero-shot** | MODA 96.3%. 비교: Marqo 92.6%, VLM 4B 92.6%, VLM 8B 88.9% | **대체 가능.** 다만 WALF 어휘에 원피스·모자가 없다 |
| 2. 디자인 속성 JSON | Claude 식별에 포함(`strict` 도구로 형식 고정) | **8B + 스키마 강제 + 탐욕적 생성** | 스키마 준수: 강제하지 않으면 8B 3.7%, 강제하면 100%. 소재 정확도 73.7%(강제) ~ 78.9%(강제 안 함), 19장 기준. 색 90%, 10장 기준. 실루엣·디테일은 정답이 없어 사람 평가 전이다 | **조건부.** 일괄 처리용 |
| 3. 브랜드·모델 식별(웹 없이) | Claude + 웹 검색 | 없음 | 세 모델 모두 정답 0/18. 2B는 2건을 지어냈다(11.1%). 4B·8B는 모두 "모름"으로 답했다. 유명 로고 상품은 테스트에 없어 미검증이다 | **부적합** |
| 4. 추천 이유·차이점 | 규칙(`designMatch`) | 8B | 8B는 한국어 100%, 지어낸 속성 0건(10건). 4B는 한국어 10%, 2B는 0% | **조건부, 필요성 낮음.** 규칙이 이미 같은 문장을 만든다 |
| 5. 검색 키워드(한·영·일) | 규칙(`buildQueries`) | 8B | 8B는 세 언어 형식, 일본어 표기, 영어 브랜드 유지가 모두 100%다. 한국어에 한자가 섞인 경우가 8.3%다. 1건에 18.6초 걸린다 | **조건부.** 일괄 처리용 |
| 6. 상품 설명 정리 | 규칙(공식몰 페이지 파서) | 8B·2B | 브랜드 100%, 색 90%, 소재 66.7%, 지어낸 숫자 0건(12건) | **대체 가능.** 일괄 처리용 |

같은 사진 10장을 temperature 0.7로 3번씩 돌렸을 때, 세 번 모두 같은 디테일 값이 나온 비율은 10~50%였다. 탐욕적 생성(temperature 0)은 같은 입력에 늘 같은 답을 낸다. 운영에서는 탐욕적 생성을 쓴다.

### 3-2. 실패 사례

로컬 모델 실험에서 나온 것
1. **형식이 깨져 값이 사라졌다.** 8B가 27장 중 26장에서 리스트 대신 문자열(`"color": "black"`)을 냈다.
   - WALF `cleanStyle`(`server/src/catalog.ts`)은 배열만 받는다. 그래서 값 93개가 아무 경고 없이 버려진다.
   - 스키마를 강제하면 0개가 된다.
2. **어휘에 없는 소재를 다른 값으로 바꿔 골랐다.** WALF 소재 어휘에 실크가 없다.
   - 스키마를 강제한 8B는 실크 정답 6장 중 5장을 "cotton"으로 골랐다.
   - 스키마를 강제한 4B는 한 장에 소재 6종을 모두 나열했다.
3. **브랜드를 지어냈다.** 2B가 Amazon 자체 브랜드 신발·가방을 "Celine", "Burberry"로 답했다.
4. **한국어 키워드에 다른 문자가 섞였다.** 2B는 16.7%, 8B는 8.3%였다. 4B는 형식이 깨진 출력 1건에서 "고跟"을 냈다(4B의 0%는 형식이 맞은 출력만 센 비율이다). 2B는 출력이 중간에 잘려 JSON이 깨지기도 했다.
5. **실루엣 값에 서술문을 넣었다.** 2B가 "a long, full-length dress with a fitted bodice…" 같은 문장을 넣었다. 어휘를 강제하지 않으면 정형 데이터가 되지 않는다.

FreeLLMAPI 코드 대조에서 나온 것(실행 미검증)

6. **페이지 열람 도구가 깨진다.** `web_fetch`를 서버에서 처리하지 않고 빈 함수 도구로 바꾼다.
   - 그러면 WALF 식별·탐색 흐름에 `tool_use`가 돌아온다.
   - WALF는 서버가 처리한다고 가정하고 결과를 보내지 않으므로 흐름이 멈출 가능성이 높다.
7. **비용이 잘못 집계된다.** 응답 `model`에 실제 모델이 아니라 요청한 Claude 이름이 그대로 들어간다. 그래서 `cost.ts`가 무료 호출을 Claude 단가로 센다.
8. **안전 분기가 동작하지 않는다.** `refusal`·`pause_turn` 신호가 나오지 않고, 도구의 `strict`도 버려진다.

## 5. 보안·라이선스 제약

**사용자 사진**
- 무료 등급 중 다수가 입력을 학습·제품 개선에 쓴다(Gemini, NVIDIA 체험판, Mistral 무료, 키 없는 Kilo).
- FreeLLMAPI의 `auto` 라우팅은 사진이 이런 곳으로 갈 수 있다. 새로 설치하면 키 없는 제공업체를 자동으로 켠다.
- 결론: 사용자 사진은 로컬 모델이나, 학습에 쓰지 않는다고 명시한 곳에만 보낸다. 지금 권하는 조합(MODA, 로컬 8B)은 외부로 사진을 보내지 않는다.

**약관**
- NVIDIA 체험판은 운영 사용을 금지한다.
- Groq는 요금 회피 목적의 사용을, OpenRouter는 재판매를, Cerebras는 키 양도를 금지한다.
- 무료 키 여러 개를 묶어 상업 서비스의 백엔드로 쓰는 방식 자체가 약관과 충돌할 수 있다.
- FreeLLMAPI 저장소도 스스로 "개인 실험용, 운영용 아님"이라고 밝힌다.

**FreeLLMAPI 자체의 위험**(부록 A §2·§7)
- 1인이 관리하고 릴리스가 매우 잦다. 보안 문서의 지원 버전 표기는 낡았다.
- 제공업체 계정이 정지된 사례가 3건 있다.
- DB 파일은 암호화하지 않는다. 대시보드 Playground는 프롬프트와 이미지를 통째로 저장한다.
- `curl | bash`로 설치한다.

**모델·데이터 라이선스**
- Qwen3-VL 2B·4B·8B는 Apache-2.0이다.
- MODA는 MIT지만, 모델 카드상 학습 데이터의 계보를 추가로 확인해야 한다(Lab `docs/DATA_LICENSE_MATRIX.md`).
- Marqo-FashionSigLIP과 SigLIP 2는 Apache-2.0, FashionCLIP은 MIT다.
- 테스트 사진 중 ABO는 CC BY 4.0이라 결과를 공개할 때 출처를 표기해야 한다.

**운영 원칙은 그대로 둔다.** 로컬 모델이 만든 태그도 AI 결과다. 운영자가 확인하기 전에는 사용자에게 보이지 않게 한다. 사용자에게 "구매 가능"이라고 말하지 않는다.

## 6. 도구 판정

| 도구 | 판정 | 이유 |
|---|---|---|
| **EGM**(Google Elephant-Goldfish Model) | **조건부, 시험할 가치 있음** | 대화 맥락 없는 리뷰어가 설계 문서를 실제 코드와 대조한다. 지금 가진 도구에는 이 기능이 없다. 훅·MCP·텔레메트리도 없다. 다만 초기 버전(v0.1.1)이고, 리뷰 보고서를 영어로 쓰게 돼 있고, 결과 파일을 작업 폴더에 쓴다 |
| **Claude Code Setup**(Anthropic 공식) | 조건부, 우선순위 낮음 | 읽기 전용 추천 스킬 1개라 위험은 거의 없다. 하지만 기존 `/init`·`update-config`와 겹친다. 새 프로젝트를 시작할 때 한 번 쓸 정도다 |
| **Claude-Mem** | 도입 불필요 | 지금 쓰는 파일 메모리와 세션 기록 스킬과 겹친다. 모든 도구 활동을 요약 모델로 보낸다(대화형 설치는 외부 호스팅이 기본값). 텔레메트리와 자동 업데이트가 기본으로 켜져 있고, 전역 설정과 셸 파일을 고친다 |
| **21st.dev MCP** | 도입 불필요 | 웹 React·Tailwind용이라 Expo 앱과 맞지 않는다. 키와 결제가 필요하고, 코드와 프롬프트가 외부로 간다 |
| **FreeLLMAPI** | 도입 불필요 | 운영에 쓸 수 없다. WALF의 텍스트 작업은 이미 규칙으로 0원이라 실험용으로도 얻을 것이 적다 |

### EGM으로 찾아줘·기다려줘 설계와 코드를 대조하는 방안

`docs/`를 통째로 넣으면 안 된다. WALF 문서는 Gate마다 덧붙인 이력이라, 옛 문서와 현재 코드의 차이가 대량으로 나와 진짜 결함이 묻힌다. 가볍게만 봐도 이런 차이가 있다.
- `WALF_V2_ARCHITECTURE.md` §4의 가격 소스 표는 차단 목록 방식이다. 지금 코드(`sources.ts`)는 허용 목록 방식이다.
- 같은 표에서 29CM·후루츠패밀리는 "PENDING_INTEGRATION"이다. 지금 코드에서는 `UNSUPPORTED`다.

그래서 순서를 이렇게 권한다(자세한 규칙 표는 부록 B §4).
1. **현재 명세 두 장을 만든다.** 찾아줘 9개 규칙(`FIND-01~09`)과 기다려줘 10개 규칙(`WATCH-01~10`)을 각각 한 파일로 정리한다. 규칙마다 코드 위치와 기존 테스트 이름을 단다.
2. **설치 없이 먼저 해 본다.** 맥락 없는 서브에이전트에 명세와 `server/src`만 주고, 규칙 ID별로 일치·불일치·판단 불가를 근거 파일·행과 함께 한국어로 받는다.
3. **나온 차이를 세 가지로 나눈다.** 코드 결함, 문서가 낡음, 의도된 차이. 어느 쪽을 고칠지는 사용자가 정한다.
4. **규칙을 테스트로 고정한다.** 테스트 이름에 규칙 ID를 붙이고, 명세의 규칙마다 테스트가 있는지 `npm run verify`에서 확인한다.
5. **그다음에 EGM으로 같은 결과가 나오는지 비교한다.** 설치는 사용자가 직접 한다. 결과 폴더는 저장소 밖으로 지정하고, 한국어 출력을 지시한다. `egm-bootstrap`은 README를 곳곳에 만들므로 돌리지 않는다.

## 7. 권장 적용 순서

| 순서 | 할 일 | 비용·조건 | 누가 정하나 |
|---|---|---|---|
| 1 | **Claude 기준선을 잰다.** 같은 27장(또는 Gate 1·2 평가셋)으로 Claude 식별을 돌려, 무료·로컬 결과와 같은 기준으로 비교한다 | 유료 호출. 27장 × 약 $0.30 = 약 $8(가정) | 사용자 승인 필요 |
| 2 | **어휘를 정한다.** 소재에 실크·벨벳, 카테고리에 원피스·모자를 넣을지 정한다 | 제품 결정. 넣지 않으면 모델이 다른 값을 고른다(실패 사례 2) | 사용자 |
| 3 | **카테고리를 MODA zero-shot으로 정한다.** R2에서 서버에 올리기로 한 MODA 임베딩에 카테고리 문장 임베딩만 더한다 | 추가 비용 0원 | 1·2 뒤 구현 |
| 4 | **`cleanStyle`이 문자열 하나도 받게 한다.** `"black"`을 `["black"]`으로 받는다. Claude는 `strict` 도구라 영향이 없고, 다른 모델의 형식 실수에 대비하는 방어다 | 코드 몇 줄 + 테스트 | 바로 할 수 있음 |
| 5 | **카탈로그 일괄 태깅을 시험한다.** 비슷한 옷 후보의 소재·색·디테일을 8B + 스키마 강제 + 탐욕적 생성으로 맥에서 태깅한다. 결과는 검수 전 상태로 넣고, 운영자 표본 검수 뒤 쓴다 | 외부 비용 0원. 1시간 약 270장(계산값) | 2 뒤 |
| 6 | **Claude 식별 범위를 줄인다.** MODA 이미지 검색 + 품번 규칙 + 공식몰 검색으로 먼저 찾고, 확인이 필요한 경우만 Claude를 부른다. 모델 교체(Opus → Sonnet·Haiku)도 기준선 결과를 보고 정한다 | 1,000명 기준 월 약 $213 → 약 $25(가정) | 기준선 뒤 사용자 승인 |
| 7 | **EGM 대조를 한다.** §6의 순서대로 명세 두 장 → 무설치 리뷰어 → 테스트 고정 → EGM 비교 시험 | 토큰 사용량 미확인 | 설치는 사용자 |

추천 이유(`designMatch`)와 검색어(`buildQueries`)는 지금 규칙을 그대로 둔다.

## 8. 기존 WALF 제품 코드에 미치는 영향

**이번 검토로 바뀐 것은 없다.** 제품 코드, 운영 API 설정(`WALF_AI_*`), 서버 사양 모두 그대로다.

권장안을 적용하면 바뀌는 곳은 다음과 같다.

| 위치 | 변화 | 크기 | 주의할 점 |
|---|---|---|---|

| `server/src/ai.ts`·`cost.ts` | 바꾸지 않음 | — | FreeLLMAPI를 붙이면 `web_fetch` 흐름이 깨지고 비용 집계가 틀어진다. 그래서 붙이지 않는다 |
| 서버 사양 | 바꾸지 않음 | — | 로컬 VLM은 4 GB·2 vCPU 서버에 올리지 않는다 |

## 9. 미검증으로 남은 것

- **Claude 유료 기준선.** 같은 사진으로 돌린 적이 없다(순서 1).
- **무료 API 품질.** Groq·Cerebras의 `qwen3.8-27b`, Cloudflare 비전 모델은 키 입력과 외부 전송이 필요해 돌리지 않았다.
- **실루엣·디테일 정확도.** 정답이 없어 사람 평가 전이다(`PENDING_HUMAN_EVALUATION`).
- **유명 로고 상품의 브랜드 식별.** 테스트 사진에 없었다.
- **지연.** 8B의 CPU 지연은 재지 않았다(4B가 이미 1회 6분). 실제 클라우드 vCPU에서의 지연도 재지 않았다. M5 CPU 수치는 하한이다.
- **로컬 장비의 전기·장비 비용.**
- **무료 한도.** Gemini 모델별 무료 한도, Mistral 무료 한도, Cloudflare Neuron 환산, Groq 한도표가 어느 플랜 값인지.
- **FreeLLMAPI 동작.** 모두 코드 대조 결과이며 실행해서 확인하지 않았다(`output_config`·`fallbacks` 처리, 키 없는 제공업체를 완전히 끌 수 있는지).
- **EGM.** 실제 토큰 사용량, 한국어 출력 지시를 따르는지.
