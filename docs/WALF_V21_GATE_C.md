# WALF V2.1 · Gate C 보고 — 기다려줘 새 매물 탐색과 대체 추천 연결

- 작성: 2026-11-19 · 브랜치 `feat/walf-v2.1`(Gate A·B 위에 이어서)
- 범위: 지시서 STEP 4(기다려줘 기능 확대)와 STEP 5(기다려줘 대체 상품 추천)
- 기존 상품 페이지 가격 감시는 그대로 두었어요. 기존 기다려줘 테스트(V2 E2E 19단계)도 모두 통과해요.
- 새 매물과 대체 상품은 **운영자가 검수한 것만** 사용자에게 보여요.

## 1. 두 작업으로 나눴어요

| | 상품 페이지 가격 감시(Price Watch) | 새 매물 탐색(Listing Discovery) |
|---|---|---|
| 무엇을 | 사용자가 등록한(또는 운영자가 연결한) 상품 페이지 **한 곳**의 가격·재고 | 같은 상품을 파는 **다른 판매처·새 매물** |
| 작업·기록 | `price_checks` → `price_observations`(기존) | `offer_searches(purpose=discovery)` → `offers(watch_id)` |
| 주기 | 하루 한 번(기존) | 하루 한 번(`ensureDiscoveries`). 같은 조회 창에서는 한 번만 |
| 결과 위치 | 상태 문장 · 가격 기록 | 앱 “새 판매처” 구역 · 어드민 기다려줘 상세 |
| 알림 | 그 페이지가 조건을 충족하면 바로(기존 규칙) | **운영자가 확인한 뒤** 원하는 가격·사이즈 조건을 충족하는 판매처만. 같은 판매처는 한 번 |
| 서로의 영향 | 새 매물 탐색 결과는 가격 감시 상태·알림·기록을 바꾸지 않아요 | 지켜보는 상품 페이지는 탐색 결과에서 빼요(그 페이지는 가격 감시 몫) |

두 작업이 서로를 바꾸지 않는 것은 테스트로 확인했어요(`[분리]`, E2E).

- 가격을 확인해도 새 매물 후보가 생기지 않아요.
- 새 매물 탐색은 가격 기록·`last_state`·`alerted`·상태·URL·페이지 동일성을 바꾸지 않아요.

## 2. 사용자가 정하는 조건(STEP 4)

- **원하는 사이즈 · 목표 가격 · 색상 · 새 상품만/중고 포함:** 기존 기다려줘 조건을 그대로 써요. 새 매물 탐색도 같은 조건으로 판단해요.
- **새 판매처도 찾아보기:** 등록 화면과 상세 화면에서 켜고 끌 수 있어요(기본 켜짐).
- **찾아볼 곳 고르기:** 상세 화면에서 판매처를 하나씩 고를 수 있어요.
  - 지금 쓸 수 있는 곳만 고를 수 있어요.
  - 지원하지 않거나 연동을 기다리는 곳은 회색으로, 쉬운 말 이유와 함께 보여요. 예: 번개장터 → “이용약관상 자동으로 찾을 수 없어요 · 필요하면 왈프 팀이 직접 확인해요”, 네이버 → “연결을 준비하고 있어요”, AI 웹 검색 → “유료 기능이라 아직 쓰지 않아요”.
  - 조항 같은 근거는 어드민에만 보여요.
  - 서버에서도 막아요. 지원하지 않는 곳을 고르려 하면 400 오류로 거절해요.
  - 사용자가 끈 곳은 탐색 기록에 “이 기다려줘에서 끈 판매처예요”로 남고, 열지 않아요.
- **감시할 상품:** 찾아줘에서 확인한 상품(품번·시즌 포함)을 우선 써요. 없으면 사용자가 쓴 상품명·브랜드를 써요. 링크만 등록해 이름을 모르면 새 매물 탐색을 하지 않아요.

## 3. 새 매물 → 알림 후보(검증)

```
같은 상품 판정(품번 일치 또는 브랜드·상품명 80% 이상)
  + 원하는 사이즈가 품절·없음이 아님
  + “새 상품만”이면 중고 제외
  → 운영자 알림 후보(어드민 대기열 “기다려줘: 새 판매처 후보”)
  → 운영자가 사진·옵션을 열어 확인하고 공개(같은 상품 확인 / 같은 상품일 수 있음) 또는 제외
  → 공개한 판매처가 원하는 가격(배송비 포함 총액, “배송비 제외”를 고르면 상품가) 이하 + 원하는 사이즈 재고 + 상태 조건이면 알림
```

- 사진 비교(매물 이미지 검증)는 연결 전이라, 그 단계를 **운영자 확인**이 맡아요.
- 알림 문구는 페이지를 읽은 시각을 함께 적고, “구매 가능”이라고 쓰지 않아요.
  - 같은 상품 확인: “…왈프 팀이 같은 상품인지 확인했어요. 먼저 팔릴 수 있어요.”
  - 같은 상품일 수 있음: “…같은 상품일 수 있어요. 확인하지 못한 점을 함께 적었어요.”
- 다음 날 다시 찾으면 이미 본 판매처는 “처음 본 곳”이 아니에요. 공개·제외 검수는 새 줄이 이어받고, 같은 판매처 알림은 다시 가지 않아요.

## 4. 기다리는 동안 볼 대체 상품(STEP 5)

- “아직 찾는 중이에요. 기다리는 동안 볼 수 있게 디자인이 비슷한 옷을 골라 봤어요” 구역을 원래 상품과 따로 보여 줘요. 카드에 “같은 상품 아님”을 표시해요.
- 대체 상품은 Gate B와 같은 공통 추천 인터페이스(`SimilarProductProvider` → `curateOffers`, 디자인·실루엣 우선)를 써요. 추천 엔진이 연결되면 찾아줘와 기다려줘에 함께 붙어요.
- 사진으로 찾아줘에서 넘어온 기다려줘만 디자인 정보가 있어 고를 수 있어요. 링크만 등록한 기다려줘는 “디자인 정보가 없어요”로 건너뛰어요.
- **저장:** 공개된 대체 상품을 저장하거나 해제할 수 있어요(`offer_saves`).
  - **저장하거나 열어 봐도 기다려줘는 끝나지 않아요.** 테스트로 확인했어요.
  - 다른 사람의 후보나 공개 전 후보는 저장할 수 없어요(404).
- 알림은 기다려줘마다 하루 한 번(“기다리는 동안 볼 비슷한 옷을 골라 봤어요”), 기록도 하루 한 줄이에요.

## 5. 지원하지 않는 플랫폼

| 판매처 | 이번 상태 | 사용자에게 보이는 말 |
|---|---|---|
| 번개장터·솔드아웃·무신사·W컨셉 | UNSUPPORTED — 열지 않아요 | 이용약관상 자동으로 찾을 수 없어요 · 필요하면 왈프 팀이 직접 확인해요 |
| KREAM·중고나라·후루츠패밀리·29CM | PENDING_INTEGRATION — 열지 않아요 | 약관·연동을 확인하고 있어요 |
| 네이버 쇼핑 API | PENDING_EXTERNAL_SETUP(키 대기) | 연결을 준비하고 있어요 |
| AI 웹 검색 | PENDING_EXTERNAL_SETUP(유료) | 유료 기능이라 아직 쓰지 않아요 |
| 브랜드 공식몰(카페24) | 등록된 브랜드만 SUPPORTED | 찾아볼 수 있어요 / 이 브랜드 공식몰은 아직 등록 전이에요 |

검색하지 않은 곳을 “매물 없음”으로 표시하지 않아요. 실제 기다려줘에는 테스트 판매처를 보여 주지 않아요.

## 6. 검증

| 검증 | 결과 |
|---|---|
| 서버 단위 테스트 | **109개 통과**(Gate B 103 + 기다려줘 6: `[분리]` `[새 매물]` `[검수·알림]` `[설정]` `[대체 상품]` `[일정]`) |
| E2E | **BADBLOOD 20 + V2 19 + V2.1 17단계 통과**(V2.1에 Gate C 3단계 추가, 계정 삭제 검사 확대) |
| 앱 타입 검사 | 통과 |
| 시뮬레이터 시각 검수 | 상품 페이지가 없는 기다려줘에서 새 판매처 카드 3개(같은 상품 확인 1 · 같은 상품일 수 있음 2) · 찾아볼 곳 고르기 · 비슷한 옷 저장을 확인 |

**V2.1 E2E에 더한 Gate C 단계**

1. 기다려줘를 등록해요. 상품 페이지가 없어 가격 감시는 확인 대기예요.
   - 새 매물 탐색은 따로 돌아 알림 후보 3곳을 찾아요.
   - 번개장터 등은 “찾지 않는 곳”으로 나와요.
   - 검수 전에는 앱에 아무것도 보이지 않아요.
2. 운영자가 검수하면 앱에 새 판매처 2곳이 보여요.
   - 원하는 조건(173,100원 ≤ 180,000원 · M 재고)을 충족한 곳만 알림이 1번 가요.
   - 가격 감시 상태·기록은 그대로예요.
3. 비슷한 옷을 공개하고 저장해요.
   - 저장해도 기다려줘는 계속돼요.
   - 지원하지 않는 판매처는 고를 수 없어요.
   - 공개 전 후보는 저장할 수 없어요.

**계정 삭제**: 기다려줘의 새 판매처·대체 상품 후보와 저장한 옷 기록도 함께 지워져요. 판매처 상품 페이지 기록은 개인 정보가 아니라서 남아요.

**시뮬레이터에서 찾아 고친 것**

- 같은 상품일 수 있음 후보의 알림이 “같은 상품인지 확인했어요”로 나가던 것
- 대체 상품을 공개할 때마다 기록이 한 줄씩 쌓이던 것 → 하루 한 줄로 바꿈
- 카드 태그가 네 개라 두 줄로 넘치던 것 → “원하는 가격 이하”를 가격 아래 확인 줄로 옮김
- 찾아볼 곳 설명에 약관 조항 번호 같은 운영자용 문장이 보이던 것 → 쉬운 말로 바꾸고 근거는 어드민에만

## 7. 한계

1. **실제로 새 판매처를 찾을 수 있는 곳은 공식몰 1곳(BADBLOOD)뿐이에요.** 중고·리셀 새 매물은 약관·제휴를 기다려요. 지금 구조로는 “새 매물이 올라오면 알림”을 실제 중고 플랫폼에서 할 수 없어요.
2. **매물 사진 검증은 운영자가 해요.** 자동 사진 비교가 연결되기 전까지 새 매물 알림은 운영자 확인 속도만큼 늦어요.
3. **새 판매처를 기다려줘의 상품 페이지(가격 감시 대상)로 바꾸는 기능은 넣지 않았어요.** 운영자가 어드민 목록에서 페이지를 연결하는 기존 방법만 있어요.
4. **링크만 등록한 기다려줘는 새 매물 탐색·대체 상품을 하지 않아요.** 상품 이름과 디자인 정보가 없어서예요.
5. **실제 기기에서의 푸시는 확인하지 않았어요.** 앱 안 알림 목록과 서버 알림 기록으로만 확인했어요(Apple Developer 계정 대기).
