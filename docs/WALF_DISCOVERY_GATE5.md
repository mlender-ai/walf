# WALF Discovery Upgrade · Gate 5 (찾아줘·기다려줘 UX)

기준일: 2026-11-20
브랜치: `feat/walf-discovery-upgrade` (mlender-ai/walf#3)

이번 Gate는 지시서 §5(검색 결과 UX)를 반영했다. 기존 디자인 시스템(1차 시안 토큰, 포인트 컬러 없이 형태·명도로 상태 구분)은 그대로 두었다. 결과 화면을 세 갈래로 나누고, 원본 옷과 대체 상품을 눈으로 구분할 수 있게 했다.

## 1. 결과 화면 구조

화면 순서는 다음과 같다.

1. **맡긴 옷**(사용자가 올린 사진과 적은 정보). 회색 바탕 띠로, 화면 맨 위에 둔다.
2. **결과 머리말**. 결과 갈래별 문구로 보여 준다.
3. **판매처**(같은 상품).
4. **회색 띠**: 비슷한 디자인의 옷, 비슷한 스타일의 브랜드(둘 다 같은 상품 아님).

| 결과 | 머리말 | 보여 주는 것 | 다음 행동 |
|---|---|---|---|
| **정확히 찾음**(`outcome=exact`) | "같은 옷을 찾았어요" | <ul><li>브랜드·모델·품번·시즌</li><li>**확인한 근거**</li><li>확인하지 못한 것(있을 때만)</li><li>근거 페이지</li><li>판매처 사진(있을 때만, "맡긴 사진이 아니에요" 표시)</li><li>판매처 카드(사이즈·가격·상태)</li></ul> | 카드 안에 버튼을 바로 둔다.<ul><li>**원하는 가격 기다리기**(주 버튼)</li><li>7일 동안 매물 찾기</li><li>저장만 하기</li></ul>예전의 확인 창 단계는 없앴다 |
| **유력 후보만**(`likely`) | "이 옷일 가능성이 높아요" | <ul><li>'유력 후보' 표시</li><li>**맞는 점**</li><li>**아직 확인하지 못한 것**</li></ul> | <ul><li>"이 옷이 맞아요"(한 번 더 확인)</li><li>**같은 옷을 계속 찾아 드릴까요?** → 계속 찾아 주세요</li><li>비슷한 디자인</li></ul> |
| **못 찾음**(`not_found`) | "같은 옷은 아직 못 찾았어요" | <ul><li>확인하지 못한 브랜드·모델을 만들어 적지 않는다</li><li>**사진에서 읽은 것**(실루엣·소재·디테일 칩)</li><li>**아직 모르는 것**(브랜드·모델명·품번·시즌)</li></ul> | <ul><li>**계속 찾아 주세요**(주 버튼)</li><li>회색 띠의 비슷한 디자인(실루엣·디테일·소재 순)</li></ul> |

**계속 찾아 주세요**를 누르면 새 화면 없이 기다려줘 등록으로 이어진다.
- 등록 화면에 "찾아줘에서 이어서" 안내가 붙고, 상품명·사이즈·색이 미리 채워진다.
- 상품 링크가 없으면 기다려줘는 '확인 필요' 상태가 된다. 왈프 팀이 맡긴 사진으로 상품 페이지를 찾는다.
- **맡긴 사진은 기다려줘로 그대로 넘어간다**(서버 `createWatch`).

신뢰도를 숫자로 보여 주지 않는다. "확인한 근거", "맞는 점", "아직 확인하지 못한 것"으로만 나눈다. "구매 가능"이라는 표현은 쓰지 않는다.

## 2. 서버 계약 추가 (`GET /requests/:id/find`)

- `outcome`: `exact` | `likely` | `not_found`
  - 같은 옷 확인(MATCH)이나 사용자 확정이면 exact다.
  - 유력 후보만 있으면 likely다.
  - 그 밖은 not_found다.
- `original`: 맡긴 사진(서명 주소), 상품명, 브랜드, 사이즈, 색
- `understood`: `{ known: 사진에서 읽은 특징, unknown: 아직 모르는 것 }`
  - unknown은 not_found일 때만 채운다.
- `match.image`: 같은 상품으로 확인해 공개한 판매처 사진이나 상품 페이지 사진이다.
  - 사용자 사진을 상품 사진처럼 쓰지 않는다.
  - 유력 후보에는 붙이지 않는다.

기다려줘 상세(`GET /watches/:id`)의 `releases`는 Gate 4에서 넣은 판매 예정 일정이다. 앱 기다려줘 상세에 알림 줄로 보여 준다. 내용은 판매처, 시작 시각, 공식 발표 근거, 그리고 "재고·가격은 시작 후 따로 알림"이다.

## 3. 모바일 실제 흐름 확인 (iOS 시뮬레이터, iPhone 17 Pro)

- 테스트 데이터 QA 서버(4302)에 QA 앱(`app.walf.v2qa`)을 연결해, 화면을 직접 열고 눌러 봤다.
- 캡처는 `docs/qa/gate5/`에 있다(1206×2622).

| 캡처 | 확인한 것 |
|---|---|
| `01-exact.png` | 정확히 찾음: 맡긴 옷 → "같은 옷을 찾았어요" → 확인한 근거 → 버튼 3개(확인 창 없음) |
| `02-exact-sale.png` | 판매처: 실제 판매처 1곳뿐 안내, 확인한 판매처에서 못 찾음 |
| `03-likely.png` | 유력 후보 2개: 맞는 점, 아직 확인하지 못한 것, "이 옷이 맞아요" |
| `04-likely-keep.png` | 계속 찾기 상자 → 판매처(테스트 데이터 표시) |
| `05-alternatives-band.png` | 회색 띠 안의 대체 추천: "같은 상품 아님"·모의 데이터 표시, 비슷한 점·다른 점, 피드백 |
| `06-not-found.png` | 못 찾음: 사진에서 읽은 것(칩), 아직 모르는 것, 계속 찾아 주세요 |
| `07-keep-looking-form.png` | 계속 찾아 주세요 → 기다려줘 등록("찾아줘에서 이어서", 상품명 채움, 허용 목록 안내 문구) |
| `08-watch-release.png` | 등록 후 기다려줘 상세: 맡긴 사진, 확인 필요, 판매 예정 일정 알림 줄 |

**시뮬레이터에서 고친 것**
- 정확히 찾음 화면에서 확인하지 못한 점이 없는데도 "확인하지 못한 부분도 함께 적었어요"가 나오던 문구
- 기다려줘 등록의 링크 안내 문구: "번개장터·무신사 등 자동 수집을 금지한 곳은…" → 허용 목록 방식에 맞게("왈프 팀이 이용 조건을 확인한 판매처는 바로 지켜봐요. 그 밖의 링크는 왈프 팀이 직접 확인해요")

## 4. 테스트

- `cd server && npm test`: **144개 통과**
  - 새 테스트 `test/discovery-gate5.test.ts` 4개: 세 갈래, 원본, 파악한 것, 계속 찾기 시 사진 이어받기
- `npm run e2e`: 20·19·21단계 통과
- 앱 `npx tsc --noEmit`: 통과
- **테스트 수 바로잡기**: Gate 0·3·4 보고의 "단위 테스트 132개·143개"는 `node --test`로 E2E 파일 3개까지 함께 센 수였다. 표준 명령 `npm test`(단위만) 기준으로는 각각 129개·140개였다. 실패한 테스트가 없었다는 점은 같다.

## 5. 남은 것·위험

- **판매처 사진:** QA 데이터의 정확히 찾음 의뢰에는 같은 상품으로 공개한 판매처 사진이 없어, 사진이 붙은 카드는 시뮬레이터에서 보지 못했다. 서버 규칙은 테스트로 확인했다.
- **유력 후보와 '같은 상품 확인' 판매처가 함께 나오는 경우:** 식별 후보 여러 개를 찾는 기능 때문에, 머리말은 "가능성이 높아요"인데 판매처 카드에는 "같은 상품 확인"(후보 2 품번 기준)이 붙을 수 있다. 어느 후보 기준인지는 어드민에만 표시된다. 앱 카드에도 "후보 기준" 표시가 필요한지 결정이 필요하다.
- **알림 확인 범위:** 판매 예정 알림이 앱 알림 목록에 어떻게 보이는지, 실기기 푸시는 확인하지 않았다.
- **Android:** 확인하지 않았다(연결된 기기 없음).
