# WALF V2.1 · Gate D 보고 — 선호·피드백, 한 화면 검수, 보안 안정화

- 작성: 2026-11-19 · 브랜치 `feat/walf-v2.1`(Gate A·B·C 위에 이어서)
- 범위: 지시서 STEP 6(사용자 선호와 피드백) · STEP 7(관리자 검수 화면) · STEP 8(보안·안정화)
- 기존 화면·7일 정책·찾아줘/기다려줘 흐름은 그대로예요. 기존 테스트(BADBLOOD 20 · V2 19단계)도 모두 통과해요.
- 외부 배포는 하지 않았어요. 아래 “한계”의 남은 항목이 풀리기 전까지 계속 막아 둬요.

## 1. 무엇이 중요한지 고르기(STEP 6)

찾아줘 결과 화면과 기다려줘 상세의 “비슷한 디자인” 구역 위에 선택 칩 4개가 있어요. 고르지 않아도 돼요.

| 칩(앱) | 서버 값 | 정렬 규칙(디자인 요소 가중치) |
|---|---|---|
| 실루엣 | `silhouette` | 실루엣 5 · 제품군 3 · 디테일·소재 1 · 색·무드 0.5 |
| 소재·디테일 | `material_detail` | 디테일·소재 4 · 제품군 3 · 실루엣 1 · 색·무드 0.5 |
| 브랜드·아카이브 | `brand_archive` | 무드 3 · 제품군 3 · 실루엣 2 · 같은 브랜드나 아카이브 무드면 +0.15 |
| 비슷한 느낌이면 OK | `vibe` | 무드 3 · 색 2 · 제품군 2 · 나머지 1 · 기준 점수를 0.35 → 0.25로 낮춰 더 넓게 |
| (고르지 않음) | `null` | Gate B 기본 규칙(제품군 3 · 실루엣 3 · 디테일 2 · 소재 2 · 색 1 · 무드 1) |

- 고른 값은 `requests.priority` · `watches.priority`에 남아요. 기다려줘는 바꿀 때마다 기록(“추천 기준”) 한 줄이 남아요.
- 바꾸면 다음 탐색 주기에 대체 상품을 새 규칙으로 다시 골라요. 선호가 탐색 열쇠(`search_key`)에 들어가 있어서 “같은 조건 재검색 막기”에 걸리지 않아요.
- 정렬 규칙 이름은 `walf-design-rank-1:<선호|default>`로 탐색 기록(`offer_searches.ranker`)에 남아요. 피드백이 어떤 정렬에서 나왔는지 나중에 구분할 수 있어요.
- 정렬은 테스트 큐레이터 데이터로만 확인했어요. 실제 추천 엔진(패션 브레인)은 연결 전이에요(Claude가 패션 모델 학습을 따로 만들지 않음).

## 2. 추천 피드백(STEP 6)

**직접 평가** — 비슷한 디자인(대체 상품) 카드에만 있어요.

- 마음에 들어요(`like`) · 비슷하지만 원하는 느낌은 아니에요(`not_quite`) · 관심 없어요(`not_interested`)
- “관심 없어요”를 누르면 카드가 접히고 “되돌리기”가 생겨요. 되돌리면 `cleared`가 남아요.
- 같은 상품 판매처에는 남길 수 없어요(400). 같은 상품 판매처는 “이 옷이 마음에 드는지”를 묻는 대상이 아니라서예요.

**행동 기록** — 만족으로 치지 않아요.

- 판매 페이지 열기(`open`), 저장(`save`), 저장 해제(`unsave`)
- `explicit=0`, 내보낼 때 `satisfaction=null`이에요. 지시서의 “단순 클릭을 추천 만족으로 간주하지 않는다”를 그대로 따랐어요.

**한 건에 함께 남는 것**(`offer_signals`)

- 상품: 후보 ID · 상품 페이지 열쇠(`url_key`) · 브랜드 · 상품명 · 관계(같은 상품/비슷한 디자인) · 공개 등급
- 추천: 추천 엔진 · 버전 · 정렬 규칙 · 그때의 순위 · 점수
- 상황: 찾아줘/기다려줘 · 그때 고른 선호 · 확인한 상품 ID · 모의 여부 · 시각

**막는 것**

- 자기 찾아줘·기다려줘의 **공개된** 후보에만 남길 수 있어요. 다른 사람 후보·공개 전 후보는 404예요.
- 선호를 바꿔 대체 상품을 다시 고르면 같은 옷이 새 줄(새 후보 ID)이 돼요. 화면에 보이는 평가·저장 표시는 같은 찾아줘/기다려줘 안에서 상품 페이지(`url_key`) 기준으로 이어 보여 줘요. 기록 자체(그때의 순위·버전)는 바꾸지 않아요.

## 3. 한 화면 검수(STEP 7)

어드민 의뢰 상세의 “한 화면 검수 →”(`/admin/requests/:id/review`)에서 한 화면에 모아 봐요.

| 구역 | 내용 |
|---|---|
| 사용자 원본 | 사진(서명 주소) · 메모 · 상품명 · 사이즈 조건 · 고른 선호 |
| AI 식별 | 순위별 식별 결과 · 서버 판정 등급 · 신뢰도 · 근거 · 사진에서 읽은 디자인 |
| 공개·확인 상태 | 운영자가 공개한 식별 결과 · 확인한 사람 · 이어진 기다려줘 |
| 같은 상품 후보 · 다른 판매처의 매물 | 찾아줘 판매처 탐색과 기다려줘 새 판매처를 함께. 품번·브랜드·상품명·색·사이즈 일치(✓)·불일치(✕)·확인 못 함(?)·사진 비교 안 함(–) · 가격·총액 · 원하는 옵션 재고 · 검수 상태 |
| 비슷한 디자인 추천 | 점수 · 추천 엔진·버전 · 순위 · 디자인 요소 표(제품군·디테일·소재·색·무드 일치 ✓/불일치 ✕) · 사용자 피드백 집계 |
| 출처와 검증 상태 | 판매처별 탐색 결과·찾지 않은 곳과 이유 |
| 검수 기록 | 이 의뢰와 이어진 기다려줘의 운영자 결정 전체 |

화면의 자동 판정은 점선, 운영자 결정은 실선 배지로 구분해요.

**검수 기록(`review_log`)** — 운영자가 판단할 때마다 한 줄씩 남아요. 자동 판정(`auto`)과 운영자 결정(`action`)을 나란히 둬서, 나중에 자동 판정이 얼마나 맞았는지 셀 수 있어요.

| 대상(`subject`) | 언제 | 남는 것 |
|---|---|---|
| `identity` | 찾아줘 결과 공개 | 서버 판정 등급·신뢰도·품번 대 운영자 등급 · 이름을 고쳤으면 고치기 전/후 · 확인 근거 |
| `discover` | 비슷한 스타일 브랜드 공개 | 점수·근거·상태 |
| `offer` | 판매처 후보·대체 상품 검수 | 자동 판정(관계·일치 판정·항목별 결과·점수·순위·엔진 버전·가격) 대 운영자 결정(같은 상품 확인/가능성/대체/제외/숨김) · 근거 · 기다려줘면 조건 충족 여부 |
| `watch_url` | 기다려줘에 상품 페이지 연결 | 이전/새 주소 |
| `watch_page` | 상품 페이지 동일성 확인 | 자동 판단 대 같은/다른 상품 |
| `shipping` | 배송비 확인 | 이전/새 배송비 |

어드민 “검수 기록” 탭에서 최근 기록을 보고, JSON으로 내보낼 수 있어요. 형식은 [`WALF_EVAL_DATA.md`](WALF_EVAL_DATA.md)에 있어요.

## 4. 보안·안정화(STEP 8)

### 4-1. 세션 — 기기 ID만으로는 들어올 수 없어요

- 전에는 기기 ID(`x-walf-device`)만 알면 그 사용자로 요청할 수 있었어요.
- 이제 처음 세션을 열 때 서버가 토큰을 한 번 주고(서버에는 해시만 저장), 그 뒤 요청은 기기 ID와 토큰(`x-walf-token`)이 함께 맞아야 해요.
- 토큰 없이 같은 기기 ID로 세션을 다시 열면 거절해요(401 `device_claimed`). 앱은 이 경우 새 기기 ID로 다시 시작해요.
- 이전 버전 앱 계정(토큰 없음)은 다음 세션 열기 때 토큰을 받아요. 그 전까지는 기존처럼 동작해요.

### 4-2. 사용자 사진 — 서명·만료가 있는 주소로만

- 업로드 폴더를 공개 경로(`express.static`)로 열지 않아요.
- 서버가 화면(앱 응답·어드민)을 만들 때만 서명한 주소(`?exp=…&sig=…`)를 줘요. 최대 13시간 뒤 만료돼요.
- 서명이 없거나 틀리거나, 만료 시각을 늘리거나, 파일 이름에 경로를 넣으면 403이에요.
- 서명 비밀값은 `WALF_SECRET`(server/.env)이에요. 없으면 서버를 켤 때마다 새로 만들어서, 재시작하면 이전 주소는 열리지 않아요(화면을 새로 열면 다시 받아요).

### 4-3. 오알림 방지 — 이전 규칙을 다시 확인했어요

이번에 새로 넣은 코드는 없어요. 아래 규칙이 그대로인지 테스트로 다시 확인했어요.

- 운영자가 확인한 후보만 알림이 가요.
- 원하는 가격(배송비 포함 총액)·사이즈 재고·상태 조건을 모두 충족해야 해요.
- 배송비·색상을 확인하지 못했으면 알리지 않아요(PR #1 리뷰 반영분).
- 같은 판매처는 한 번만 알려요. 모의 알림은 푸시하지 않아요.
- 어느 문구에도 “구매 가능”을 쓰지 않아요.

### 4-4. 중복 검색·AI 비용

- 같은 조건의 판매처 탐색·대체 상품 고르기는 20시간 안에 다시 열지 않고 결과를 재사용해요(Gate A·C).
- 선호를 바꾸면 조건이 달라진 것이라 새로 골라요. 같은 선호로 몇 번 눌러도 다시 고르지 않아요.
- 유료 AI는 월 예산·의뢰별 호출 상한(`cost.ts`)을 그대로 지켜요. 끊긴 유료 작업은 자동으로 다시 돌리지 않아요.
- 판매처 탐색·추천 정렬은 AI를 부르지 않아요.

### 4-5. 사용자 데이터 삭제

계정을 지우면 이렇게 돼요.

| 데이터 | 처리 |
|---|---|
| 추천 피드백·행동 기록(`offer_signals`) | 지워요 |
| 저장한 옷(`offer_saves`) | 지워요 |
| 세션 토큰 | 지워요(계정 줄이 남는 경우에도) |
| 사진·찾아줘·기다려줘·알림 | 기존 정책대로 지워요 |
| 운영자 검수 기록(`review_log`) | 상품·판매처 판단이라 남겨요. 대신 사용자의 찾아줘·기다려줘와의 연결(`request_id`·`watch_id`)을 끊어요 |
| 내보낸 평가 데이터 | 사용자를 가명(`u_` + 12자리)으로만 넣고 사진·메모·기기 정보는 넣지 않아요 |

**V2.1 E2E에 더한 Gate D 단계**

1. 보안
   - 기기 ID만으로 요청하면 401이에요.
   - 남의 기기 ID로 세션을 새로 열 수 없어요.
   - 사진은 서명 주소로만 열리고, 서명 없음·위조·경로 조작은 403이에요.
2. 선호·피드백
   - 소재·디테일을 고르고, 비슷한 디자인에 “마음에 들어요”·“관심 없어요”를 남겨요.
   - 같은 상품 판매처에는 평가를 남길 수 없고, 판매 페이지 열기는 행동 기록으로만 남아요.
3. 한 화면 검수
   - 사용자 원본 사진 · AI 식별 · 같은 상품 후보와 기다려줘 새 판매처 · 디자인 요소 ✓/✕ · 피드백 집계 · 출처 · 검수 기록이 한 페이지에 나와요.
4. 평가 데이터 내보내기
   - 피드백은 모델 버전·순위·선호와 함께, 사용자는 가명으로 나와요.
   - 검수 기록은 자동 판정(가능성)과 운영자 결정(같은 상품 확인)·근거가 나란히 나와요.
   - 모의 데이터는 기본으로 빠져요.

**계정 삭제**: 피드백·저장·토큰이 지워지고, 검수 기록은 남되 의뢰·기다려줘 연결이 끊긴 것을 확인했어요.

**화면 검수에서 찾아 고친 것**

- 선호를 바꿔 대체 상품을 다시 고르면 남긴 평가·저장 표시가 사라지던 것 → 같은 상품 페이지 기준으로 이어 보여 줌
- 다시 고른 뒤 옛 순서와 새 순서가 섞여 보이던 것 → 최근 고른 결과가 먼저 오게 정렬
- 어드민 디자인 요소 표에서 불일치(✕) 글자가 아주 크게 나오던 것 → 기존 숫자 스타일과 이름이 겹친 CSS 클래스를 바꿈

## 6. 한계

1. **피드백은 아직 추천 순서에 반영하지 않아요.** 지금은 쌓아서 내보내기만 해요. 추천 엔진(패션 브레인)을 연결할 때 이 데이터를 쓰는 것이 다음 단계예요.
2. **앱 토큰은 AsyncStorage에 저장해요.** iOS 키체인(SecureStore)으로 옮기려면 네이티브 모듈을 넣고 앱을 다시 빌드해야 해서 이번에는 하지 않았어요.
3. **`WALF_SECRET`을 설정하지 않으면 재시작마다 바뀌어요.** 어드민 로그인과 사진 주소가 만료돼요. 실제 운영 전에 server/.env에 고정 값을 넣어야 해요.
4. **HTTPS가 아니에요.** 같은 네트워크 안에서는 토큰이 평문으로 오가요. 외부 배포 전에 HTTPS가 필요해요. 그래서 외부 배포는 계속 막아 둬요.
5. **실제 기기 푸시는 확인하지 않았어요**(Apple Developer 계정 대기).
6. **운영자 계정은 하나예요.** 검수 기록의 운영자 이름은 로그인 때 적은 이름이고, 사람별 권한은 없어요.

|---|---|
| `server/src/media.ts` | 사진 서명 주소 만들기·검증 |
| `server/src/domain.ts` · `api.ts` · `index.ts` | 토큰 세션(`openSession` · `tokenOk`) · 사진 경로 교체 · 선호·피드백·열기 API · 계정 삭제 범위 확대 |
| `server/src/feedback.ts` | 선호 저장 · 피드백·행동 기록 · 화면용 평가·저장 표시 · 평가 데이터 내보내기 |
| `server/src/reviewlog.ts` | 검수 기록 남기기·읽기 |
| `server/src/curation.ts` · `findsearch.ts` | 선호별 정렬 규칙 · 정렬 규칙 이름을 탐색 기록에 |
| `server/src/find.ts` · `offerreview.ts` · `watch.ts` · `discovery.ts` | 결정마다 검수 기록 · 화면에 선호·평가 |
| `server/src/admin.ts` | 한 화면 검수 · 검수 기록 탭 · 내보내기 |
| `server/src/db.ts` | `users.token_hash` · `requests/watches.priority` · `offer_searches.ranker` · `offer_signals` · `review_log` |
| `app/src/lib/api.ts` · `components/PriorityPicker.tsx` · `components/OfferCard.tsx` · `app/find/[id].tsx` · `app/watch/[id].tsx` | 토큰 저장·전송 · 선호 칩 · 피드백 칩·접기 |
| `server/test/v21-gated.test.ts` · `server/test/e2e-*.ts` | Gate D 테스트 6개 · E2E 토큰 세션 · V2.1 Gate D 4단계 |
