## 1. 완료한 개발 — 실제로 작동하고 테스트를 통과한 것

- **V2 데이터 모델·마이그레이션**: 상품·변형·찾아줘 결과·브랜드 스타일·Watch·매물·가격 기록·조회 작업 표. V1 DB를 올릴 때 사본을 먼저 남기고 기존 의뢰·QA 데이터는 그대로 둠(V1 스키마 파일로 실제 업그레이드 테스트).
- **기다려줘 가격 추적 엔진(실제 데이터 소스 포함)**: 공식몰(카페24) 상품 페이지의 옵션별 재고·가격을 하루 1회 읽어 판정. 같은 페이지는 Watch가 여럿이어도 한 번만 읽음. AI 호출 없음. **가입·키 없이 실제 페이지로 동작**(위 1회 확인).
  - 정책: 활성 3개 · 하루 1회 · 30일마다 계속할지 · 일시중지·재개·종료 · 상품 정보 불명확 시 확인 요청(운영자가 상품 페이지 연결) — 모두 환경변수로 조절.
  - 판정: 사이즈·색상 옵션 · 품절 · 재고 미확인 · 표시 할인가 · 같은 상품 미확인 매물을 구분하고, 모두 확인될 때만 “기다리던 가격이 됐어요”.
  - 배송비를 알면 상품가+배송비로 비교, 모르면 “배송비 미확인”으로만 표시.
  - 중복 알림 방지(조건이 깨졌다 다시 맞을 때만 다시 알림), 서버 재시작 후 끊긴 조회 회수, 연속 실패 시 “확인 불가” 알림 1번.
- **찾아줘 결과 분류·공개**: AI 제안을 서버 규칙으로 MATCH·LIKELY·숨김으로 나누고(근거 주소 없는 MATCH 금지), 운영자가 공개한 것만 사용자에게. 사용자 확인 → 상품 저장 → 7일 매물 찾기 / 기다려줘 / 저장만. “아니에요” → 어드민 대기열로.
- **DISCOVER 큐레이션**: 브랜드 37개·스타일 태그 256개(공식 소개·패션 매체 출처 있음, 운영자 검수 전) + 사진 스타일과 2종류 이상 겹치는 브랜드만. “같은 상품 아님” 표시. 어드민에서 태그 검수.
- **비용 가드레일**: 월 예산·의뢰별 호출 상한·같은 조건 검색 재사용·호출별 추정 비용 기록·예산 초과 시 보류 → 운영자 확인 후 계속·재시작 시 유료 작업 자동 재실행 안 함·모의 실행은 집계 제외.
- **보안 보강**: 서버가 여는 상품 링크의 SSRF 방지(내부망·비표준 포트·로그인 정보·리다이렉트), robots.txt·약관 차단 목록, 기기별 쓰기 요청 제한, 계정 삭제 시 기다려줘·사진 삭제.
- **어드민**: 찾아줘 결과 공개, 기다려줘 목록·상품 페이지 연결, 비용·예산, 스타일 매핑 검수, 대기열 3종 추가.
- **앱**: 홈 두 진입로(찾아줘·기다려줘), 찾아줘 결과, 기다려줘 등록·상세(가격 기록·조건 변경·상태 변경), 추적함 “내가 찾는 옷” 통합 목록. 기존 캐릭터·흑백 톤·7일 수배 여정·출발 애니메이션은 그대로.

## 4. 비용 및 기술적 위험

### 비용(자세히: [비용 모델](WALF_V2_COST_MODEL.md), 모두 가정)
- 사용량 비례 비용은 찾아줘 AI뿐이에요. Opus 5.5 기준 10명 약 $14 · 100명 약 $137 · 1,000명 약 $1,368/월. 그중 7일 탐색이 70% 이상.
- 기다려줘 가격 확인은 외부 API 비용 $0(3,000 Watch도 하루 329MB 트래픽).
- 1,000명 규모는 Anthropic Start 티어 월 상한($500)을 넘어서 티어 상승이 필요해요.

### 보안 점검(STEP 7)

| 항목 | 상태 | 내용 |
|---|---|---|
| 사용자 인증·권한 | **미해결 — 외부 공개 전 필수** | 앱이 만든 기기 ID(UUID)를 헤더로 보내는 방식. 기기 ID를 알면 그 사용자로 행동할 수 있어요. 남의 의뢰·Watch는 404로 막지만(단위·E2E 테스트), 서명된 세션 토큰이나 로그인 도입이 필요 |
| 업로드 사진 접근 제어 | **미해결** | `/uploads/<UUID>`는 주소를 알면 누구나 열 수 있어요(추측은 어려움). 서명된 기한부 주소로 바꾸는 작업 필요 |
| 상품·매물 URL 검증 | 해결 | 서버가 여는 링크는 SSRF 방지·robots·약관 차단. 앱 입력은 http(s)만 |
| 사용자별 API 사용 제한 | 해결(서버 1대 기준) | 기기별 쓰기 10분 60회. 여러 서버로 늘리면 공용 저장소로 옮겨야 함 |
| AI 호출 예산 제한 | 해결 | 월 예산·의뢰별 상한·보류·운영자 확인 |
| 관리자 인증·세션 | 대체로 해결 | HMAC 서명 쿠키(HttpOnly·SameSite=Strict·12시간), CSRF 토큰, 로그인 10회 실패 시 10분 잠금. `WALF_SECRET`을 정하지 않으면 재시작마다 로그아웃. 운영자 개인 계정·2단계 인증은 없음 |
| 사진·민감 정보 보존·삭제 | 일부 | 계정 삭제·사진 교체 시 삭제. **기간 기준 자동 삭제 정책은 없음**(정책 결정 필요). AI를 켜면 사진이 Anthropic으로 전송됨 → 개인정보 처리방침 반영 필요 |
| DB 마이그레이션·백업 | 일부 | 스키마를 올릴 때 사본 생성. **정기 백업은 없음**(호스팅 결정 후) |
| 환경변수·비밀키 | 해결 | 키·비밀번호는 `.env`만(저장소 제외), 커밋한 파일에 키 없음 |

→ **지금 구조로는 외부에 공개하지 말고 로컬 테스트 환경을 유지**해야 해요(인증·사진 접근 두 항목).

### 기술적 위험·제약
- 공식몰마다 페이지 구조가 달라요. 카페24·schema.org가 아닌 곳은 “가격·옵션을 읽지 못했어요”로 실패 처리돼요(성공처럼 보이지 않음).
- 공식몰이 약관을 바꾸거나 봇을 막으면 그 판매처는 “확인 불가”가 돼요. 판매처 차단 목록은 코드에 있어 배포가 필요해요.
- 중고 매물은 아직 자동으로 볼 수 없어요(약관·API). 기다려줘의 “중고도 괜찮아요”는 지금은 새 상품 페이지만 봐요(화면에 “연동 준비 중” 표시).
- 표시 할인가(회원가·쿠폰)는 적용 조건을 몰라 목표가 비교에 쓰지 않아요 → 실제로는 살 수 있는데 알림이 안 갈 수 있어요(보수적 선택).
- 브랜드 스타일 seed는 출처가 있지만 운영자 검수 전이에요. 일부 태그는 시즌·협업 하나가 근거예요(태그마다 근거 문장 보관). BADBLOOD는 공식 소개 글이 없어 seed에서 빠졌어요.
- 스케줄은 서버 메모리 타이머예요. 서버가 꺼져 있던 동안의 확인은 켜질 때 몰아서가 아니라 다음 시간 창에 한 번 해요.

## 5. 다음 개발 우선순위(외부 설정 후)

1. **실 API 연결 확인**: 키·예산 설정 → 찾아줘 5건으로 토큰·검색 횟수 실측 → 비용 모델의 가정을 실측값으로 교체 → 모델·effort 결정.
2. **찾아줘 정확도 평가 세트**: 제품명이 정확한 옷 · 브랜드만 아는 옷 · 아카이브 · SNS 착용 사진 · 케어라벨 · 비슷한 다른 제품(FAR FROM WHAT vs ANDROS) · 찾기 어려운 사례로 10건 이상을 정답과 함께 만들고, 브랜드 일치율 · 모델·시즌 일치율 · 잘못된 MATCH 비율 · 근거 주소 유효성 · 비용 · 시간을 기록(그럴듯한 오답 MATCH를 가장 심각한 실패로).
3. **외부 공개 전 보안**: 서명된 세션 토큰, 사진 기한부 주소, 사진 보존 기간 정책, 정기 백업.
4. **스타일 매핑 검수**: 운영자가 seed 태그를 확인(특히 단일 근거 태그), 우리 사용자들이 자주 찾는 브랜드부터 추가.
5. **중고 플랫폼**: 중고나라 법무 결과에 따라 자체 검색 연결(실험 브랜치에서 검증한 방식) + 새 매물 동일성 판단(규칙 선별 후 Haiku).
6. 공식몰 외 쇼핑몰 형식 추가(실패 로그를 보고 많이 쓰이는 형식부터).

## 미완료·하지 않은 것

- 실제 Anthropic API 호출, 실제 정확도 수치 — 키 없음.
- 중고 플랫폼 데이터 수집 — 약관·API 확인 전이라 구현하지 않음(UNSUPPORTED·PENDING_INTEGRATION).
- 외부 배포·도메인·TestFlight — 보안 항목과 계정 대기.
- 새 이미지 임베딩·벡터 검색 — 이번 범위 밖(열쇠 구조만 맞춰 둠).
- 앱 네이티브 빌드로 새로 설치 — 시뮬레이터는 기존 Release 앱에 새 JS 번들을 넣은 테스트 앱으로 확인했어요. 실기기 설치(`npm run iphone`)는 하지 않았어요.
