## 2. 무엇을 만들었나

### 처리 흐름

```
의뢰 접수 ─▶ 사진 분석(맥 안, Qwen3-VL) ─▶ 상품 후보 ─▶ 운영자 확정 → 7일 시작
매일 1회  ─▶ 판매처별 검색(SearXNG) ─▶ 상품 페이지 확인(Crawl4AI) ─▶ 규칙 판정 ─▶ 운영자 검수 ─▶ 앱
```

### 구성

| 부분 | 쓰는 것 | 비고 |
|---|---|---|
| 사진 분석·사진 비교 | Ollama + `qwen3-vl:8b-instruct` | 맥 안에서만 실행. 사진이 밖으로 나가지 않음 |
| 검색 | SearXNG (Docker, 이 맥에서만 열림) | 네이버·빙·브레이브만 켬 |
| 페이지 정보 | Crawl4AI (헤드리스 크롬) | 구조화 데이터(JSON-LD) 우선. 차단 회피 기능은 켜지 않음 |
| 판정 | 규칙 코드(`engine/rules.py`) | 색·사이즈·구매글·판매 완료·같은 상품 여부 |

### 기존 시스템과의 관계

- **분리:** 실험은 별도 작업 폴더(`.claude/worktrees/oss-hunt-7d`)와 별도 서버(포트 4301, DB 따로)에서 돈다. 지금 앱이 쓰는 서버(4300)와 main은 바뀌지 않았다.
- **켜는 법:** 기존 Claude 공급자는 그대로 있고, `WALF_AI_PROVIDER=oss`일 때만 새 엔진이 켜진다.
- **검수:** 운영자 검수는 그대로다. AI 결과는 검수 전까지 사용자에게 보이지 않고, 엔진은 '구매 가능'을 판정하지 않는다.
- **어드민:** 이렇게 늘었다.
  - 매물마다 페이지 상태, 색·사이즈 일치 여부, 근거
  - 운영자 검수 시간 입력란
  - 7일 실험 리포트(`/admin/report`)
- **기록:** 작업마다 원본 로그(`server/data/hunt-logs/`)와 그때의 코드 버전(커밋)이 남는다.
- **테스트:** 기존 서버 테스트 46개, BADBLOOD E2E 20단계, 엔진 판정 테스트 10개가 모두 통과한다.

## 5. 단계별 진단

### 5-1. 검색 — 가장 큰 문제

| 검색 엔진 | 결과 | 쓸 수 있나 |
|---|---|---|
| 네이버 | 거의 매번 응답. **제목은 정확함**(예: "배드블러드(BADBLOOD) 미스틱 나일론 트랙 자켓 - 네이비"). 하지만 **링크가 상품 페이지가 아니라** 판매처 첫 화면·후기 화면임 (`musinsa.com/main/musinsa/recommend`, `soldout.co.kr/`) | 제목만 단서로 쓸 수 있음 |
| 빙 | 자주 "연결 오류". 응답해도 한국어 `site:` 검색에 엉뚱한 결과(유튜브 고객센터, 노래 가사 등) | 거의 못 씀 |
| 브레이브 | 처음 몇 번은 상품 주소를 줌. 3번째 검색쯤 "요청이 너무 많음" → SearXNG가 1시간 정지. 8초 간격으로 늦춰도 첫 검색부터 막힘 | 지금은 못 씀 |
| 구글 | "접근 거부" | 우회하지 않고 뺌 |
| 덕덕고 | CAPTCHA | 우회하지 않고 뺌 |

**확인한 것:** 처음에는 SearXNG의 네이버 연결 코드가 결과의 엉뚱한 링크를 가져온다고 의심했다. 그래서 임시 사본에서 "제목에 달린 링크"를 가져오도록 고쳐서 같은 검색을 다시 해 봤다. **결과가 똑같았다.** 즉 SearXNG 쪽 버그가 아니라, 네이버 웹 검색이 원래 그 페이지들로 연결하고 있다.

**첫 시험의 숫자(TEST B, 검색 27회):**

| 항목 | 값 |
|---|---|
| 검색 결과 | 74건 |
| 상품 주소처럼 생긴 것 | 33건 (대부분 무신사 **해외몰** global.musinsa.com) |
| 중고장터 상품 주소 | 번개장터 2건, 중고나라·후루츠패밀리 0건 |
| 걸린 시간 | 2분 10초 |

### 5-2. 페이지 수집

판매처의 robots.txt를 일반 수집기(`*`) 기준으로 따른다.

| 판매처 | robots.txt (일반 수집기) | 실제 수집 결과 |
|---|---|---|
| 29CM | 허용 | 상품명·가격·판매 상태를 구조화 데이터로 읽음. 판매 완료 판정 정상 |
| 번개장터 | 허용 (AI 회사 수집기만 따로 차단) | 가격·판매 완료는 본문에서 읽힘. 상품명은 제목에 안 잡힘 → 검색 제목으로 보충 |
| 중고나라 | 허용 | 시험한 글이 삭제된 글(404)이라 '삭제'로 정상 처리 |
| 후루츠패밀리 | 허용 (AI 회사 수집기만 따로 차단) | 화면을 늦게 그려서 상품 정보가 비어 있음 → 더 기다렸다 다시 읽게 했지만 아직 확인 못 함 |
| 무신사 | **전부 막음** (`Disallow: /`) | 열지 않음. 검색 결과 제목만 씀 |
| W컨셉 | **전부 막음** (`Disallow: /`) | 열지 않음. 검색 결과 제목만 씀 |

**발견한 문제:** Crawl4AI의 기본 robots.txt 확인은 robots.txt 요청이 막히면(무신사는 보안 장치가 403으로 막음) "허용"으로 처리한다. 그래서 첫 시험에서 무신사 페이지를 열었다. 이제는 엔진이 robots.txt를 직접 읽는다. 자동으로 못 읽으면 2026-11-09에 사람이 확인해 저장한 원문(`engine/robots/`)을 따르고, 그것도 없으면 열지 않는다.

### 5-3. 사진 분석 (로컬 모델)

| 모델 | 사진 1장 | 결과 |
|---|---|---|
| `qwen3-vl:8b` (thinking) | 2~3분 | 답하기 전에 오래 '생각'함. 짧은 글자 요청도 2분 안에 안 끝남 → 쓰지 않음 |
| `qwen3-vl:8b-instruct` | **36초** | 가슴 지퍼 포켓까지 잡음 → **채택** |
| `qwen3-vl:4b-instruct` | 22초 | 포켓을 '작은 포켓'으로만 봄 |

- **단점:** 같은 사진도 실행마다 소재 판단이 달라지고, 없는 특징을 가끔 만든다. 그래서 소재는 '추정'으로만 쓴다.
- **한글 표기:** 로컬 모델이 만든 한글 표기(BADBLOOD → "바드블러드", "마스틱 나이론")는 틀려서 검색어로 쓰지 않는다. 대신 검색 결과 제목의 "배드블러드(BADBLOOD)" 같은 표기와 운영자 메모에서 배운다.

### 5-4. 판정 규칙

첫 실행에서 "Mystic" 한 단어만 같아도 같은 상품으로 봐서 **모자·타월·팬츠까지 25건을 '같은 상품으로 보임'으로 판정했다.** 고친 내용은 다음과 같다.

- **옷 종류가 같아야 한다.** 자켓을 찾으면 결과도 자켓이어야 한다.
- **소재·라인 단어가 하나 이상 맞아야 한다.** (나일론·트랙 등)
- **해외 판매용 사이트는 국내 판매처에서 뺀다.** (global.musinsa.com 등)
- **다른 색 페이지는 근거로 쓰지 않는다.**
- **같은 상품은 주소가 달라도 하나로 본다.** (제목 slug·추적용 주소 차이 무시)

### P0. 검색 소스 (이걸 바꾸지 않으면 7일 실행이 의미 없음)

| 방안 | 장점 | 단점·확인할 것 |
|---|---|---|
| **A. 네이버 검색 API** (쇼핑·카페 검색) | 공식·무료(하루 25,000회). 쇼핑 검색은 상품명·가격·판매처·**상품 링크**를 줌(무신사·29CM·W컨셉 입점 상품). 카페 검색으로 중고나라 글도 찾을 수 있음 | developers.naver.com에서 애플리케이션 등록·키 발급이 필요(직접 해야 함). 번개장터·후루츠패밀리는 안 나올 수 있음 |
| **B. 판매처 자체 검색 페이지 수집** | 29CM·번개장터·중고나라·후루츠패밀리는 robots.txt가 일반 수집기의 검색 페이지 접근을 막지 않음. 매물을 가장 직접적으로 찾을 수 있음 | 각 판매처 **이용약관**이 자동 수집을 막는지 확인 필요. 번개장터·후루츠패밀리는 AI 회사 수집기를 명시적으로 막고 있어 취지상 민감함 |
| C. Brave Search API | 공식 API, 무료 한도 있음 | 가입·키 필요. 결제 수단 등록이 필요한지 확인 필요. 한국어 쇼핑 결과 품질은 미확인 |
| D. 지금 그대로 | 추가 작업 없음 | 이번 결과대로라면 매물을 거의 못 찾음. 검색 엔진 약관상 자동 조회 허용도 분명하지 않음 |

**제안:** A(네이버 검색 API)를 먼저 붙인다. 중고장터(번개장터·후루츠패밀리)는 약관 확인 뒤 B를 판단한다.

### P1. 사진 식별 방식

- 사진만으로 브랜드·모델을 찾는 건 지금 무료 수단으로는 어렵다. 설명 검색어로는 상품이 안 나온다.
- **현실적인 방식은 이렇다.**
  1. 사진 분석은 특징 요약과 운영자 참고용으로만 쓴다.
  2. 브랜드는 사용자 입력이나 운영자 확정으로 정한다.
  3. 확정 뒤에는 이름·품번으로 탐색한다.
- 검색 소스가 고쳐져 후보 이미지가 생기면 "사진 ↔ 후보 이미지 비교"(이미 구현됨)를 다시 검증한다.

### P1. 무신사 · W컨셉

- robots.txt가 일반 수집기를 전부 막으므로 페이지를 열지 않는 것이 맞다.
- 가격·재고는 네이버 쇼핑 API 같은 공식 경로로만 받는다.

### P2. 판매처 범위

- 이번에 상품이 실제로 있던 곳은 **브랜드 공식몰**(badblood.co.kr), **솔드아웃**, **KREAM**, **POIZON**이었다.
- 지시서의 판매처 6곳에는 없다. 국내 공식몰·리셀 플랫폼을 넣을지 정해야 한다.

### P2. 7일 운영 환경

- 맥이 꺼지거나 잠들면 그날 탐색은 '하지 못함'으로 남는다. 지금은 `caffeinate`로 잠들기만 막고 있고, 뚜껑을 닫으면 잠들 수 있다.
- 재부팅하면 Docker(SearXNG)와 실험 서버를 다시 켜야 한다. Ollama는 자동으로 켜진다.
- **GitHub Actions는 맞지 않는다.**
  - 8B 모델을 CPU로 돌려야 한다.
  - 검색 엔진이 데이터센터 IP를 더 쉽게 막는다.
  - DB가 맥에 있다.
- **Oracle 무료 VM**은 확보하지 못했다.

### P3. 측정 빈틈

- **운영자 검수 시간:** 직접 입력해야 기록된다. 입력이 없으면 리포트에 '입력 없음'으로 나온다.
- **Claude 비교:** 기준 데이터가 없다. 유료 호출은 하지 않았다.
